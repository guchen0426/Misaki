# 广告小游戏还原项目大纲

## 1. 项目目标

- 把“广告里看起来很好玩，但下载后货不对板”的小游戏玩法提炼出来，做成真正可玩的网页合集。
- 首发先放在浏览器中试玩，快速收集反馈，再决定哪些玩法最值得迁移到微信小程序。
- 只提炼通用玩法框架，不直接复刻他人品牌、角色、美术或剧情包装。

## 2. 调研结论

### 2.1 高传播广告玩法类型

1. 拉针救援
   - 常见元素：水、火、岩浆、金币、怪物、受困角色。
   - 核心体验：顺序决策 + 即时失败反馈。
   - 广告优势：3 秒内看懂，失败戏剧性强。

2. 停车解堵
   - 常见元素：目标车辆、拥堵车阵、出口箭头。
   - 核心体验：空间规划 + 拖拽解谜。
   - 广告优势：看一眼就知道目的，容易激发“我来帮他挪一下”。

3. 画线护送
   - 常见元素：小狗、国王、婴儿、蜜蜂、石头、激光。
   - 核心体验：临场补救 + 生存倒计时。
   - 广告优势：高压感强，特别适合“错误示范 -> 用户想接管”。

4. 数学门跑酷
   - 常见元素：乘法门、加成门、士兵数量、僵尸群。
   - 核心体验：即时成长 + 爽感结算。
   - 广告优势：数值变化醒目，容易延展成长和排行榜。

5. 螺丝拆板
   - 常见元素：螺丝、木板、盒槽、被困角色。
   - 核心体验：拆解顺序 + 微型匹配。
   - 广告优势：动作反馈密集，适合长线关卡化。

6. 错误选择剧情
   - 常见元素：穿搭、修房、避险、角色关系。
   - 核心体验：情绪反差 + 二选一纠错。
   - 广告优势：人物和剧情包装空间大，适合后续商业化活动页。

### 2.2 这类广告为什么会火

- 目标简单：几乎都能在极短时间内解释清楚“救谁、避开什么、怎么赢”。
- 失败夸张：错误往往是立刻死亡、爆炸、翻车，很容易引发情绪。
- 代入感高：广告经常故意演示错误操作，让观众产生“我上我能行”的冲动。
- 成本可控：大多数玩法都能用轻量 2D 实现，适合浏览器和小程序。

## 3. 首发原型范围

### 3.1 第一批上线玩法

1. 拉针救援
   - 用于验证顺序谜题是否足够抓人。
   - 重点观察：首关理解速度、错误反馈、重开意愿。

2. 停车解堵
   - 用于验证拖拽手感和路径规划的复玩性。
   - 重点观察：拖拽流畅度、关卡难度、是否有“再来一关”的动力。

3. 画线救狗
   - 用于验证画线长度限制和倒计时压迫感。
   - 重点观察：画线容错、物理反馈、失败后是否愿意立刻重试。

### 3.2 第二批候选玩法

- 数学门跑酷
- 螺丝拆板
- 错误选择剧情

## 4. 技术方案

- 引擎：Phaser 3
- 语言：TypeScript
- 构建：Vite
- UI：DOM HUD + Canvas 游戏区
- 当前目标：先做浏览器合集站，再评估迁移到微信小程序

## 5. 版本路线

### 版本 A：试玩站

- 3 个小游戏入口
- 单关原型
- 可重复重开
- 用于确认哪种玩法最上头

### 版本 B：内容化

- 每个玩法扩到 10 到 30 关
- 加入失败动效、胜利动画、关卡选择
- 增加排行榜、每日挑战、分享文案

### 版本 C：小程序化

- 适配微信分享和冷启动路径
- 增加轻量存档与回流激励
- 补小程序常用运营位和活动页
